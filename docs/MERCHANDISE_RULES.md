# Проверяемые правила коммерческой аналитики — 08.09.2026

## Уточнения после сравнения со Skill

Приоритет имеет новое задание пользователя; карта перед изменениями — [MERCHANDISE_FOLLOWUP_MAP.md](MERCHANDISE_FOLLOWUP_MAP.md).

- `status` — коммерческий результат. `preliminary_band` — только диапазон выполнения 115/85/70%. `operational_state` и `operational_signal` — отдельная диагностика. Операционные и поставочные проблемы не понижают коммерческий статус.
- Сезонное наблюдение начинается с более поздней даты: начало официального сезона или фактический коммерческий вход. Складская/плановая дата не доказывает коммерческий вход. При неизвестном входе наблюдение неизвестно. Дни включительно, не позже конца сезона. Для обычного сезона минимум 14 дней; более короткий срок допускается только при явном узкосезонном нормативе. Неверный явный норматив не заменяется.
- `earliest_status_review_date` — начало наблюдения + минимальные дни − 1 (включительный счёт). Для даты 01.09 первая допустимая оценка — 14.09. Точная дата действия — из этого правила или явного срока проверки; иначе пусто и окно 7–14 дней. Произвольный следующий понедельник исключён.
- Размерные агрегаты без утверждённого порога дают сигнал проверки, даже при 98% доступности или 8% выбитости. `sizes_ok=False` подтверждает проблему; неизвестное не становится False. Невыполненная проверка не равна проблеме. Подтверждённые поздний вход/риски второй поставки учитываются отдельно в операционной оценке.
- Предсезон: приоритет дневного факта, иначе недельный факт; граничная неделя делится 1/7 до сезона и 6/7 внутри. Известные недели суммируются с пометкой неполноты. Нет известных значений — пусто. Частичная сумма не становится доказательством продаж партии.
- Категории/сводка показывают известные суммы и покрытие. Реализация считается по парам факт/база, выполнение — по парам факт/план. Наборы независимы. Наличие базы не обязательно для сопоставимости выполнения.
- `presentation.display_units` использует Decimal ROUND_HALF_UP только на выводе. Суммирование и все отношения сохраняют raw-точность. UI использует совпадающий halfExpand. Физические единицы целые; темпы, недели, проценты и экономика дробные.
- Excel: 38 колонок артикулов, 8 действий, 4 сводки; сгруппированный QA с количеством артикулов. После прежних восьми листов добавлены месячный план, краткая история и методика. Полные доказательства и происхождение остаются в API/UI.
- Старые запуски не пересчитываются. Новые поля относятся только к новым результатам; UI поддерживает старые схемы и отсутствие новых полей.

## Входные подтверждения и прозрачность

Дополнительные точные заголовки находятся в `importers.BOOLEAN_FIELDS`, индивидуальные нормативы — в `norms.FIELDS`. Булевы значения «Да»/«Нет» или boolean, пусто — неизвестно. Поля «Нужна…» описывают подтверждённую потребность; поля «…проверена» — выполнение проверки. Это разные факты.

Даты, числа и диапазоны не взаимозаменяемы. `Утверждённый срок наблюдения, дней`, `Утверждённый срок проверки цены, дней`, `Утверждённый предел скидки`, `Норматив покрытия, недель` должны отражать решения бизнеса. Нельзя заполнять их произвольно ради получения желаемого статуса.

Доказательства расчётных диагнозов содержат использованные метрики; `input_provenance` и `plan_sources` сохраняют исходные строки и координаты. Формулы проверяются независимо на реальных значениях. Известные агрегированные суммы публикуются с покрытием; проценты — по собственным сопоставимым наборам. Качественные ограничения не скрыты за статусом IMPLEMENTED.
