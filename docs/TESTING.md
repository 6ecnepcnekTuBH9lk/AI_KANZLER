# Проверки

Дата проверки: 07.09.2026. Окружение Windows, Python 3.12.14, Node 24.19.0. Все синтетические данные создаются только в pytest fixtures и временных каталогах. В production-ресурсах фиктивных продаж и подставных ответов Alta нет.

## Автоматические проверки

Из корня проекта:

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\ruff.exe check backend scripts
.venv\Scripts\ruff.exe format --check backend scripts
```

В `frontend`:

```powershell
npm.cmd run test
npm.cmd run lint
npm.cmd run typecheck
npm.cmd run build
```

Проверено 47 backend-тестов и 3 frontend-теста. Backend включает расчётные границы, сохранение пустых значений и нулей, предсезон, граничные недели, темп, базу FACT, вторую волну, ценовые ограничения, неоднозначность ТН ВЭД, сохранение Excel, миграции при старте и перезапуск с сохранённой историей. Frontend — оба активных раздела, безопасное начальное состояние загрузки, форматирование и получение более 5000 строк.

Регрессионная проверка коммерции меняет только поле «1-я партия» в синтетическом входе и требует полного совпадения рассчитанных результатов. Это метаморфная регрессия критического правила, не сравнение с независимым эталоном всего Skill.

Тест `test_clean_database_upload_background_history_and_download` создаёт новую SQLite в отдельном временном каталоге, выполняет настоящий коммерческий service через HTTP, проверяет очередь, результат, экспорт и повторный запуск приложения. Моки Alta используются только в изолированных тестах недоступности/неоднозначности.

## Excel и UI

Коммерческий XLSX проверяется после сохранения: восемь листов, число артикулов, русские заголовки, фильтры и закрепление. `verify_delivery.py` сверяет значения сводки с JSON, ширины/высоты и целостность встроенных ресурсов относительно двух ZIP. ТН ВЭД проверяет неизменность остальных частей OOXML и исходных значений, а также текстовый формат новых кодов.

В браузере проверены загрузка реальных коммерческих входов, определение ОЗ26/06.09.2026, прогресс и 338 строк, вкладки, карточка артикула, сводка, история после перезапуска. Сквозной запуск ТН ВЭД выполнен тем же интерфейсом с живым Alta: 57 строк, 13 кодов, 44 уточнения; скачивание получило HTTP 200. Дополнительный `scripts/smoke_api.py` выполнил новый коммерческий запуск через HTTP, сверил SHA256 трёх входов и открыл оба скачанных XLSX; запись проверки — `test-results/api-smoke/jobs.json`.

## Предупреждения и границы проверки

openpyxl предупреждает о неподдерживаемых расширениях исторических книг. Эти книги открываются только на чтение; предупреждение о возможном удалении расширений не означает, что исходник был пересохранён. Для результата ТН ВЭД используется точечное изменение ZIP.

Есть предупреждения совместимости тестового клиента Starlette/httpx/AnyIO; тесты проходят. Production-сборка выдаёт предупреждение о JS-чанке больше 500 КБ: для локального приложения это не блокирует запуск, но разделение загрузки модулей остаётся оптимизацией.

Не проверены PostgreSQL, многопроцессный сервер, корпоративное развёртывание, визуальная печать отчётов в Microsoft Excel и полное совпадение с независимым экспертным результатом двух Skill. Полная чистая переустановка ОС/Node/Python не выполнялась: проверены установленное окружение, фиксированные зависимости, production build и запуск с пустой БД.
