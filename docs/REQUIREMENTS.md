# Карта требований перед реализацией

Источники: два неизменённых SKILL.md и четыре ресурса коммерческого Skill в backend/app/resources. При конфликте готовых статусов в загружаемом плане расчёт выполняется заново по Skill. Пользователь исключил старый файл прогноза W35.

| Контур | Ответственность | Критерий |
|---|---|---|
| Инфраструктура | SQLite/SQLAlchemy, миграции, файлы, задания, история | Файлы по UUID и SHA256; длительные операции вне HTTP; восстановление после рестарта |
| Импорт коммерции | Разбор смысловых многоуровневых заголовков, роли, даты, сезон | Настоящий FACT: TDSheet, 4187 строк, 186 колонок; реальные даты недель приоритетнее подписей |
| План | Поартикульная форма, точная резервная категория | Только Начальный остаток FACT; первая партия не участвует |
| Сезон | ОЗ26 01.09.2026–28.02.2027 | Предсезон отдельно; только W36–W8; граничная неделя пропорционально и с QA |
| Метрики | Темп завершённых недель, требуемый темп, прогноз, запас, возраст | Нет данных = null; ноль продаж не пропуск; никакого выдуманного GMROI |
| Решения | Статус → причина → действие → дата и роль | 115/85/70%; операционные проверки до цены; вторая волна 70% базы FACT |
| История | Три встроенных исторических XLSX | Относительная сезонная форма, точное соответствие категории; не заменяет план |
| Экспорт | Восемь листов из разделов 49–55 Skill | Русские заголовки, 9 pt, фильтр, закрепление, отдельные недели |
| ТН ВЭД | Признаки → кандидаты Alta → проверка → код/комментарий | Только однозначный подтверждённый код из 10 цифр, сохранение XLSX |
| Интерфейс | Два модуля, главная, история, настройки | Один расчётный результат для UI и Excel; без будущих фиктивных модулей |

## Границы формализации

Skill использует качественные условия «достаточная представленность», «подтверждённый спрос», «экономически обоснована», не задавая для всех них числовых порогов. Приложение не изобретает такие пороги: сохраняет доказанные отклонения, использует заданные нормативы и показывает непроверенные условия явно. Автоматическое ценовое или закупочное решение требует подтверждённых входных условий. Качественные решения и допущения сопоставляются в MERCHANDISE_RULES.md.

DOCX дополнительно задаёт пределы скидок (40/50/60%), правила линий, контроль 7–14 дней, запрет штатных перемещений магазин→магазин, нормы складских месяцев и необходимость экономического подтверждения второй волны. Корпоративные KPI за 12 месяцев не подменяются показателями одного сезонного среза.

Сравнение со старым XLSX, рассчитанным по другой базе/предсезонному окну, не является эталонной регрессией обновлённого Skill. Для полной проверки эквивалентности нужен независимый результат именно приложенной редакции Skill на тех же входах.
