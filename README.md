# KANZLER Business Platform

Локальное web-приложение для коммерческого анализа коллекций и заполнения ТН ВЭД. Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, SQLite; React, TypeScript, Vite, Ant Design, Recharts. Два модуля и общая история операций. Интерфейс на русском.

## Запуск на этом компьютере

Зависимости установлены в `.venv`, frontend собран. В PowerShell из папки проекта:

```powershell
.\start.ps1
```

Откройте http://127.0.0.1:8000. Для остановки нажмите Ctrl+C в терминале сервера. Не запускайте второй экземпляр на том же порту. Миграции применяются автоматически при запуске, база создаётся в `data/database/platform.db`.

## Установка с нуля

Нужны Python **3.12+** и Node.js **22.12+** (проверено с 3.12.14 и 24.19.0). Встроенный Python этого компьютера по команде `python` — 3.10, он не подходит. Укажите путь к Python 3.12:

```powershell
.\setup.ps1 -Python 'C:\путь\к\Python312\python.exe'
.\start.ps1
```

`setup.ps1` создаёт окружение, устанавливает зафиксированные зависимости из `requirements.lock.txt` и `frontend/package-lock.json`, собирает frontend. Глобальные пакеты и исходные Excel не изменяются. Если политика PowerShell запрещает сценарии, выполните команды из сценариев вручную в терминале; изменение системной политики не требуется.

## Разработка

```powershell
.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
cd frontend
npm.cmd run dev
```

Vite открывается по http://127.0.0.1:5173 и проксирует `/api` в backend. Описание API: http://127.0.0.1:8000/docs.

## Работа с модулями

**Коммерческая аналитика:** загрузите одновременно актуальный поартикульный план, план из ценообразования и FACT. Роли, сезон и дата распознаются автоматически. При действительном конфликте появятся поля уточнения. После завершения доступны восемь разделов и Excel. Нажатие на артикул открывает расчёты, недельную траекторию, историю продаж, проверки перед ценой и качество данных.

Поле `1-я партия` не используется в объёмных расчётах. ОЗ26 ограничен 01.09.2026–28.02.2027. Предсезонный факт показывается отдельно. Для граничной недели без дневных данных применяется доля календарных дней с явным сообщением QA.

**ТН ВЭД:** загрузите XLSX с номенклатурой и характеристиками. Уже заполненные коды по умолчанию сохраняются. Непроверенные или неоднозначные коды остаются пустыми, причины добавляются в комментарий. В карточке видны признаки, кандидаты и источник подтверждения. Требуется доступ к `https://www.alta.ru`. Результирующий XLSX сохраняет исходную структуру: редактируются только необходимые OOXML-ячейки.

В **Истории** можно вновь открыть результаты и скачать файлы после перезапуска приложения. Настройки показывают активные параметры и встроенные ресурсы.

## Хранение

```text
backend/app/resources/   неизменённые Skill, DOCX и исторические XLSX
data/uploads/            загруженные файлы по UUID
data/results/            результаты по UUID задания
data/database/           SQLite
data/platform.log        технический журнал ошибок
```

Настройка через переменные окружения `KANZLER_DATA_DIR` и `KANZLER_DATABASE_URL`. Для PostgreSQL потребуется установить драйвер и указать URL SQLAlchemy. SQL-модели не содержат колонок на каждую неделю: недельные значения хранятся строками. Перенос данных между СУБД выполняется отдельно.

Миграции вручную:

```powershell
.venv\Scripts\alembic.exe upgrade head
.venv\Scripts\alembic.exe current
```

## Область применимости первой версии

Некоторые качественные положения Skill не задают машинных порогов и требуют операционного подтверждения: ходовые размеры, достаточная представленность, экономическая допустимость второй поставки. Приложение показывает эти ограничения и не назначает скидку или полный забор по недоказанным условиям. Автоматический классификатор не покрывает все технические подсубпозиции ТН ВЭД; такие позиции выводятся для уточнения, без подстановки приблизительного кода. Независимый эталонный результат приложенной редакции Skill пока не предоставлен — полная эквивалентность с ним не заявляется.

Сложная корпоративная авторизация не включена по заданию. Сервер по умолчанию слушает только 127.0.0.1; опубликования в сеть и внешнего хостинга нет.
